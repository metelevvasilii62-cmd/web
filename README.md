# Прототип новостного агрегатора

**Тема: политика и право.**

Скрипт `aggregator.py` читает список RSS-лент из `sources.txt`, скачивает
каждую ленту один раз, склеивает свежие новости с историей в `data/news.json`
(дубли по ссылке убираются, новости старше 72 часов удаляются) и генерирует
статичный адаптивный `index.html` из `template.html`.

## Запуск локально

```bash
python aggregator.py
```

**Зависимости:** только стандартная библиотека Python 3 (см. `requirements.txt`),
`pip install` ничего не ставит. Нужен Python 3.9+ (использована 3.15).

После запуска появятся/обновятся:

- `data/news.json` — история новостей (заголовок, источник, время, ссылка, фрагмент);
- `index.html` — страница со списком по времени, открывается с диска без интернета.

Даты хранятся в UTC, на сайте показываются в московском времени (МСК, UTC+3),
формат заголовка «Обновлено»: `ДД.ММ.ГГГГ ЧЧ:ММ (МСК)`.

## Как это работает

1. `sources.txt` — по одной RSS-ленте на строку; строки с `#` игнорируются.
2. `urllib.request` скачивает каждую ленту **один раз** за запуск, таймаут 15 с.
   Ошибка одной ленты логируется и не мешает остальным. Если не загрузилась
   ни одна лента — скрипт завершается с кодом 1 и **не трогает** `index.html`.
3. `xml.etree.ElementTree` разбирает RSS 2.0. Берутся только `title`, `link`,
   `pubDate`, `description`/`summary`. `content:encoded`, картинки и полные
   тексты не используются.
4. Анонс очищается от HTML-тегов и обрезается до 250 символов.
5. История сливается со свежими, дубли по ссылке удаляются, новости старше
   72 часов удаляются. Если лента временно недоступна — прежние новости
   в `data/news.json` остаются.
6. `index.html` собирается из `template.html`: JSON вместо `__NEWS_JSON__`
   (с экранированием `</` → `<\/`), дата свежей новости в МСК вместо
   `__UPDATED__`.
7. Полные тексты статей **не копируются** — только краткий фрагмент (≤250 симв.).

## Настройки

- **Источники:** только файл `sources.txt` (по одной ссылке на строку).
- `HOURS_LIMIT = 72` — окно актуальности в часах.
- `CONTACT_EMAIL` в `aggregator.py` — почта в User-Agent
  (`NewsAggregator/1.0 (contact: ...)`). Замените `your@email.com` на свою.
  Ту же почту поставьте в подвал `template.html`.
- Лимит 250 символов — в `parse_feed`.
- Отображаемые имена источников — карта `SOURCE_NAMES` в `template.html`
  (новым доменам можно добавить красивое имя).

## Публикация: автообновление и GitHub Pages

Сайт будет обновляться сам каждые 30 минут и работать, пока у вас выключен
компьютер: GitHub Actions запускает скрипт, коммитит изменения, GitHub Pages
отдаёт `index.html`. Ключей и паролей в репозитории нет — используется
встроенный `GITHUB_TOKEN`.

### 1. Создайте публичный репозиторий

На github.com: **New repository** → имя (например `news-aggregator`) →
**Public** → **Create repository** (без README и .gitignore — у вас уже есть).

### 2. Залейте проект (Windows PowerShell)

В папке проекта:

```powershell
git init
git branch -M main
git add .
git commit -m "Сборка: агрегатор новостей"
git remote add origin https://github.com/<ВАШ-ЛОГИН>/<ИМЯ-РЕПО>.git
git push -u origin main
```

Если `git push` просит логин/пароль:

- Самое простое — установите GitHub CLI: `winget install GitHub.cli`,
  затем `gh auth login` → GitHub.com → HTTPS → Login with a browser.
- Или Personal access token: GitHub → Settings → Developer settings →
  Personal access tokens → Fine-grained tokens → Generate (права Contents:
  Read and write). В PowerShell вместо пароля вводите токен.
- Или настройте SSH (Settings → SSH and GPG keys) и используйте
  `git@github.com:<ЛОГИН>/<РЕПО>.git`.

### 3. Включите GitHub Pages

Репозиторий → **Settings → Pages** → Build and deployment → Source:
**Deploy from a branch** → Branch: **main**, folder **/ (root)** → **Save**.
Через минуту сверху появится адрес сайта:
`https://<ВАШ-ЛОГИН>.github.io/<ИМЯ-РЕПО>/`.

### 4. Запустите workflow вручную в первый раз

Вкладка **Actions** → workflow **Update news** → **Run workflow** →
**Run workflow**. Дождитесь зелёной галочки (скачивание лент занимает
несколько минут). Если шаг «Fetch news» красный — откройте его лог: там
видно, какая лента не отвечает.

### 5. Проверьте расписание

Во вкладке **Actions** появляются запуски каждые 30 минут (cron задан в UTC).
Первая автоматическая смена `index.html` — в течение часа. Сверить можно по
строке «Обновлено: … (МСК)» в шапке сайта.

## Если обновления остановились

1. **Actions** → последний прогон: красный? смотрите логи шагов
   «Fetch news» и «Commit changes».
2. Надпись «Skipped due to inactivity» — GitHub отключает расписание у
   неактивных репозиториев (нет пушей/запусков 60+ дней). Любой пуш или
   ручной запуск возвращает расписание.
3. Проверьте `sources.txt` — источники могли сменить адреса лент.
4. Убедитесь, что коммиты идут от `github-actions[bot]` и в настройках
   Pages источник — `main` / root.
5. Сайт не открывается вообще — проверьте, что `index.html` лежит в корне
   репозитория, и пересохраните настройки Pages.

## Замечания

- Некоторые новости без `pubDate` пропускаются.
- `data/news.json` хранит только то, что нужно странице: заголовок, источник,
  время, ссылка, анонс ≤250 символов.
- Лента недоступна — прежние новости не пропадают, но старше 72 часов
  удаляются при следующем успешном запуске.
